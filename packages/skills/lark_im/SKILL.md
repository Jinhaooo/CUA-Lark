# 飞书 IM 通用工作流

## 工具使用约束（demo 模式）

**本会话内禁止调用 `ocr_locate` / `ocr_read`**。OCR 当前实现慢（单次 15-20 秒）且会匹配到错误实例（如"发送给"在群成员卡片、消息引用框、底部占位符里都出现，OCR 返回首匹配多半不是想要的位置）。

需要在截图里定位元素时：
- **首选肉眼判断坐标**——你看到截图，直接给出 `click({x:..., y:...})`
- 拿不准坐标用 `vlm_locate(prompt)`，让另一次 VLM 推理给坐标
- 只在系统级原生窗口才考虑 `uia_find`（飞书界面 a11y 关时已被禁用，看 `## 可用工具` 段）

任何针对"特定联系人或群组"的 IM 任务，都遵循三段式：

1. **定位会话**——左侧会话列表能直接看到目标会话标题，就点击进入；
   看不到，按 `Ctrl+K` 调出搜索框，输入名字关键词，从结果里选目标
2. **进入会话**——点会话项后，先截图看顶部聊天标题；
   不是目标 → 退到第 1 步重新选；是目标 → 进入第 3 步
3. **执行动作**——发文本：**进入正确会话后底部输入框已自动聚焦，直接 `type(text)` → `hotkey('Enter')`**，不需要再定位输入框（飞书的会话切换默认把焦点交给输入框）；
   撤回：右键最后一条消息 → 选"撤回"；其他动作类似

## 关键原则

- 判断"当前是哪个会话"的依据是**截图顶部聊天标题**，不是窗口标题、不是 url、不是其他 UI 元素
- 顶部标题与目标不一致时，**禁止直接打字**——先回到第 1 步切换会话
- 反复定位失败（搜不到 / 进了仍是错的会话）→ `call_user('找不到 X，请确认会话名是否正确')`，不要在错的会话里硬发
- 每次 `click` 切会话后，下一步必须 `screenshot` + 重读顶部标题，再决定是否打字
- **不要为了"打字"先去定位输入框**——在正确会话里，键盘输入直接进输入框；多走一轮等于白白增加延迟
- 仅当连续 `type(text)` 后截图发现内容没出现在输入框（例如焦点被弹窗抢走），才需要 `click` 输入框重新聚焦再重试
